# BCSP-FCSP 计划审阅与修订依据

2026-11-20 · 供审阅

## 🎯 审阅结论

**方向合理，建议按修订版推进一次有明确停止条件的固定粗结构对照。** 草案抓住了 PCAT 中尚未回答的问题：给定相同粗点、原生密点与进入展开头的特征，额外提供逐父局部几何能否改善密点放置。固定 256 父点、每父 32 子点和原生展开路径，配合同容量、同初态的 B0／B1，是目前最小的有效比较。直接开展四次训练之前，应先验证真实槽位映射、零残差恒等、原生输出复现及缓存成本。草案中的阶段安排用于制定协议，本次交付只做计划审阅、本机静态证据核对和文献查证。

PCAT 的 C／D 折共同粗未覆盖区恢复差为 +5.99／−5.54 个百分点，全 E 多父支持差为 +4.95／−5.11 个百分点，因此正式状态是 `NO_STABLE_ALLOCATION_SIGNAL`。G2 的 16 个新增严重病例中，14 个粗 E P95 已相对变差。D 折 41 个“粗 E P95 未变差、密 E P95 变差”的病例中，只有两个是新增严重病例。D 折 `069 random_2` 仅有 1 个远端密点，仍有密阶段恢复不足。证据支持先检验子点放置的可改空间，也说明固定粗点的方案无法覆盖多数已知严重尾例。G1/G2 原生差异只能为新实验提出问题。见 [PCAT 完整报告](../../outputs/pcat_experiment_report_20261120_v1/Cranial_BCSP_FullMamba_BCSP_PCAT_完整实验报告_zh_v1.md) 和 [冻结统计](../../outputs/pcat_P5_paired_summary_20261119_v1/paired_summary_v1.json)。

## 🔬 关键修订

| 草案问题 | 形成的修订 |
|---|---|
| “实际 FC 输入”有两种可能口径 | 本机哈希匹配的母版显示，`reduce_map` 输出传入 `decode_head`，内部还会做跨槽位最大池化再拼接。固定 `H` 为该模块的实参，内部池化后的 `patch_feature` 只用于核对，避免改变条件。静态配置的候选宽度为 384，生产张量宽度和顺序仍待实测 |
| 同容量的全局均值和局部特征也改变了逐父特征分布 | B1−B0 的主张限于“提供逐父局部描述有增量”。B1 通过时可用已训练 B1 做一次固定错配诊断，保持几何值的多重集合和其他张量。性能下降只说明模型对正确对应敏感，训练期的分布与匹配作用仍需另外做同分布配对训练 |
| B1 赢 B0 可以由 B0 退化产生 | 增设 B1−当次同源原生 N 的绝对收益与风险门，原历史 N 单列作身份复现。防止把较弱对照的退化当作方法收益 |
| 第二 seed 的启动条件在正文和附录不一致 | 只有 C、D 两折同时通过主门、原生锚点门和强化区间门，才建议另行授权四次 seed1。区间仅描述固定母版与头种子下的开发来源不确定性 |
| 840 条缓存、准入前向和最终端到端核对容易重复计数 | 每折保留 P1 一训练例与一开发例的合格采集，四条可复用记录纳入 840 条缓存。独立计总 forward、唯一缓存记录和 Head-only 预测。所有 C/D 开发结果在四个最终头冻结后统一评分 |
| “所有梯度非零”与末层零初始化不相容 | 首次反向核查输出层有限且人工例中非零，第一层由链式法则数据梯度为零。待末层有非零更新后再检查第一层，区分数据梯度与 AdamW 衰减。缓存张量在训练前验证可被 autograd 保存 |
| 仅凭 3900 步或头很小估算资源 | 保留 3900 步作为配对预算。实际开销先验证 B8、8192×8192 的原 Chamfer 前反向。FP32 完整距离矩阵单张约 2 GiB，不能从 MLP 参数量推断显存。缓存、评分和训练分别定预算 |
| 退化粗点可能被守卫隐性排除 | 对有限重复或极小尺度保留原案例，按同一公式计算并记录。非有限、资产或对齐错误才阻断，不能用降低分母换通过 |
| 子点位移上界可能使最严重病例天然不可恢复 | 固定逐坐标上界及其欧氏外包半径。用原生密点和固定界计算可达面积上界，披露其乐观性质。用它解释方案的能力范围，避免为极端例调大位移或改变粗点 |

母版静态检查依据为 [PCAT 绑定审计](../../outputs/pcat_P0_P1_readonly_20261119_v1/audit_receipt_v1.json)、[AdaPoinTr 的 FC 与损失源码](../../outputs/p1pub/models/AdaPoinTr.py) 及 [SPCG factory](../../outputs/spcg_implementation_20261116_v1/bcsp_spcg_factory_v1.py)。已查见的配置使用 `fine_coverage_weight=1`、`fine_local_weight=0`，方向 Chamfer 代码为对两向平方最近邻距离开方后各自求均值，再按方向权重合并。实际 CUDA provider 与异常处理必须按对应冻结训练运行再次确认。
