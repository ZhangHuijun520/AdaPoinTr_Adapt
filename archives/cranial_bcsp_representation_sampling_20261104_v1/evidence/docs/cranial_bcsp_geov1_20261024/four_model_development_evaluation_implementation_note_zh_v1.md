# 四模型开发集配对评价：实现与解释补充 v1

日期：2026-10-26。研究阶段：BCSP_INPUT_DENSITY_V1。本文是训练结束、模型预测开始前的实现补充，不追认新增细节为训练前预注册。

## 科研问题与边界

比较同折、同seed0、同8192点输出的8k／16k输入模型，回答增加观测点是否降低未知原始表面误差，同时改善或至少不损害切壁接口覆盖。两折各105病例，四模型合计420次native forward；42个不同颅骨来源，每来源五种缺损。四个模型均为B0 AdaPoinTr Transformer，结论用于后续Mamba路线的表示选择。

主终点、A1／A2／B参考、阈值、控制与source bootstrap完全沿用《four_model_development_evaluation_protocol_zh_v1.md》。未知表面E与切壁J按已验证的G／D体素共享面区分；没有可靠内外板解剖标签，不分别宣称内板或外板精度。离散点集距离不能证明实体无缝贴合、闭合性、可制造性或临床安全。

## 本机准备过程的版本说明

1. 几何指标20项人工CPU检查通过后，参考构建v1在首例写出前停止。原因是旧QC采用`D_J_area_mm2`保存D／G共享接口面积，工具误查`G_J_area_mm2`。v1失败记录保留，参考文件数为0。对210份QC记录逐一确认字段后，v2仅修正这一映射，改用全新输出目录；表面定义、原始mask、采样、病例、指标和阈值均不改变。v2构建前后重新核验D／G原始文件哈希，接口面数和面积须与既有QC一致。这是本次本机准备阶段的修正，不是模型重跑。
2. 服务器就绪核对v1在本机载荷SHA断言停止。Windows文本写入将LF转为CRLF；v2改为绑定原文件字节，服务器载荷文件未改。v2只读核对通过，没有安装、模型加载或CUDA调用。原捕获记录保留，不把未得到回执的v1算成服务器审计通过。
3. 控制器人工测试v1遇到Windows没有`O_NOFOLLOW`常量。v2仅在该人工fixture内模拟常量存在，生产Linux代码继续使用原来的`O_NOFOLLOW`。该项证明不覆盖写入，不构成Linux符号链接竞态的动态安全证明。
4. 最终人工测试为几何20项、推理／评分18项、控制器8项，共46项。中间版本及失败证据保留。CPU通过不证明CUDA推理已通过。

## 执行与解释限制

服务器只生成420个预测，不把GT喂入模型，不调用loss、backward、optimizer、训练态或BNCal。载入最终checkpoint时，PyTorch会反序列化其张量容器；只将`base_model`加载进模型，不恢复optimizer／scheduler，也不执行其更新。输入NPZ含历史GT字段，推理函数仅读取`partial`。

每个模型开始前固定seed0，保留最终BN running statistics，使用`eval()`及`inference_mode()`。完整model state在105例前后必须相等。资源合同采用采样监测与超限停止，不声称专属cgroup硬隔离或连续瞬时显存保障；PID仅作诊断。首次启动及失败均不得自动重试、resume或接着训练。

模型结束后给用户四个预测归档文件：tar.gz、SHA256、bytes、内容哈希清单。该归档不包含checkpoint。用户下载核验后，再绑定实际归档SHA创建本机评分执行范围；当前不伪造尚未产生的归档哈希。服务器和Windows目录不自动同步。

配对解释应同时检查E主误差、J接口指标、逆向离群及最差source。若E改善但J恶化，只能报告存在取舍；不能只挑有利指标。置信区间反映固定seed0下source差异，不覆盖训练随机性。未完成420预测或存在未执行病例时不发布完整四模型比较结论。开发集分析不能充当独立测试集最终性能，也不自动授权选模型后的额外训练。
