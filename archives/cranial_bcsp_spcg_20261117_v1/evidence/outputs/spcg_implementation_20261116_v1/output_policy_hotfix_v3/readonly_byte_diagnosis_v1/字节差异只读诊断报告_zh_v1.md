# Windows源码描述符字节差异：只读诊断

2026-11-16。未修改模型、生产守卫、候选入口或测试；未重跑CPU合同测试；无服务器或GPU操作。

## 已确认根因

四个测试绑定文件的Path.read_bytes结果均与原冻结大小、SHA256完全一致，文件没有损坏或发生内容漂移。只有新v3 entry采用CRLF换行；其他三个继承helper／UTC文件为LF。

| 文件 | 原始字节 | CRLF数 | 默认os.open/os.read返回字节 | O_BINARY返回字节 |
|---|---:|---:|---:|---:|
| parent_helper | 31713 | 0 | 31713 | 31713 |
| helper | 32728 | 0 | 32728 | 32728 |
| UTC实现 | 3563 | 0 | 3563 | 3563 |
| v3 entry | 22487 | 245 | 22242 | 22487 |

v3默认描述符读出的内容，精确等于原字节将245个CRLF替换成LF后的内容；少245bytes，首个差异偏移97。显式O_BINARY读取则与冻结原始字节逐字节相等。四文件比较前后size、mtime、ctime和inode均未变化。

因此，失败并非第一份parent_helper自身哈希错误，而是守卫按四文件顺序初始化时到达CRLF的entry后，Windows默认文本描述符进行了换行转换。原异常未带路径，故仅凭调用栈无法确定具体是哪一项；本轮已明确定位为entry。

该适配必须局限sys.platform=='win32'和人工测试进程，Linux生产入口不安装代理。新版本测试需明确记录代理的范围，并覆盖实际policy的五个精确输出、邻近NPZ拒绝、输入写拒绝、源码只读及linecache／traceback。新一批CPU执行仍须按单次、失败即停边界，不复用先前失败输出目录。
