# BCSP-TRACE计划审阅意见

日期：2026-11-17；对象：用户同日TRACE v1草案。审阅状态：仅文档、冻结源码与既有元数据核对，没有模型执行、服务器操作或实现授权。

## 一、总体意见

**研究问题合理，执行方案需要修订后再采用。** 当前最有信息价值的工作是有限地观察实际探针与Memory的关系，而不是直接投入六次训练。原计划保留母版、D-only输入、同容量G2/G3、原loss及两折验证的设计是优点；最主要的问题是将观察相关性、定义性覆盖改善与因果机制验证靠得过近。

建议批准“先D0、后决定G3”的路线，不建议直接批准完整训练矩阵。D0阴性或不确定可以正式结束本阶段，不应视为还需追加工程或参数探索。

## 二、必须修改的项目

| 原稿问题 | 为什么影响结论 | 修订版处理 |
|---|---|---|
| 要求D0区分H-A与其他解释 | 冻结权重观察没有随机干预；缺损形态可能同时影响距离和误差 | D0只给投入动机，不声称唯一归因 |
| A=S后的d1=0、Memory覆盖提升容易被当收益 | 自身邻居使其成为数学恒等结果 | 明确不计为成功；只看真实骨块误差和风险 |
| “相关不为负”可让零关联通过 | 不提供正向信息；小样本不稳 | 主相关和类型调整相关均严格>0才进入人工投入决策；不可估则不自动训练 |
| r>2、半数低支持被当客观机制门槛 | 由Memory尺度和薄骨几何决定，没有临床验证 | r/nu只作描述，连续R作为主要量；不贴临床标签 |
| “尽量不重复来源”留有后验补位 | 相同颅骨多种缺损会夸大样本独立性 | 每折严格20独立来源，类型各4，固定哈希补位 |
| 压力案例与补充案例混合求关联 | 5例已由结果挑选，会强化预期 | 固定5例单列；主关联仅其余35例 |
| 几何重算未区分FP32/FP64索引 | 极近并列下次序可变，误判实现失败 | 原生FP32分数稳定排序核对实际KNN，FP64仅几何分析 |
| 历史重放容差未精确绑定 | 旧Native合同没有已验证跨设备容差 | 提出新TRACE事前限值并注明性质；失败记不可比，不放宽重试 |
| 40例要求来源汇总不变 | 未覆盖来源内全部5缺损，不能还原原来源均值 | 仅核所选80条重放与风险，不宣称全开发集复现 |
| 初始Q聚集可被判为实现故障 | 随机初态低方差不一定是bug | 区分数值/图断连错误与待观察的模型退化；不挑初态 |
| 声称只改变锚点而忽略序列效应 | A=S同时改变空间分布与槽位配对，Mamba顺序敏感 | 结论限定为联合候选；不额外改排序来补救 |
| 全630条完整采集和40例精采样并存 | 内存、存储、实际可分析字段不确定 | 全630存P/Q及轻量统计，固定40×3=120条存完整内部字段 |
| bootstrap seed写“例如” | 尚未预注册可复核随机过程 | 固定C=2026111701、D=2026111702，保存索引矩阵 |
| “明显恶化／普遍改善”不明确 | 结果出来后容易改变晋级标准 | 给出每折、对两参照的逐指标方向及新增严重=0规则 |
| 备份状态仍停留在未核验 | 与最新归档完成回执冲突 | 更正六权重本机字节备份完成；运行恢复仍未测试 |

这些修订没有提高对科研结果的预设要求，也没有新建通用守卫框架；目的是让失败、阴性和不确定能够一次性结案。

## 三、SPCG支持的优先级

G2相对G1的E P95在C/D分别增加1.5270/1.8720mm，D折来源CI整体大于0；J P95亦回退。C折J Cover@2mm改善约7.02个百分点，但新增严重病例9例、挽回4例。D折新增7例、无挽回。因此应优先判断“空间条件为何未转化成完整形状”，而非仅优化邻域覆盖统计。

不过，这些结果没有证明Sobol探针必然落在错误空间：缺损区域原本缺乏观测点。Memory表面锚点可能改善条件质量，也可能把生成过强地绑定到已有骨面。G3值得被明确证伪，不能预设更接近输入即更好。

## 四、文献带来的实际修改

1. 3DMambaComplete的2026 v2确有Cross-Attention，不能把它当“完全无注意力”同类。应比较实际计算图，不按模型名称归类。[全文](https://arxiv.org/html/2404.07106v2)
2. FusionMamba的空间校正、Hyper-PCN的anchor协作使宽泛的“引入锚点”缺乏独占新意。TRACE应先证明D-only完整骨块预测的可靠收益，再谈创新边界。[出版社](https://www.sciencedirect.com/science/article/pii/S1566253526002575)、[CVPR](https://openaccess.thecvf.com/content/CVPR2026/html/Li_Hyper-PCN_Hypergraph-Based_Point_Cloud_Completion_via_High-Order_Correlation_Modeling_CVPR_2026_paper.html)
3. MedPCFM是任务直接相关的新参照，但采样、点数和训练预算不同；不能将文中CD与本项目分区P95直接比较。未来论文基线应单独做同协议复现，而非插进本轮机制实验。[全文](https://arxiv.org/html/2606.24433v1)
4. 临床厚度、内外板和边缘设计与合成切壁不同；不能把2mm支持指标转写成临床安全性。[PubMed](https://pubmed.ncbi.nlm.nih.gov/38430381/)

文献核验覆盖不是“全部题录全文精读”。部分官方站点后续重访出现403／反爬，已在核验表记录；不据受限页面推断未读公式或公开代码。

## 五、为什么不建议增加更多消融

锚点置换、随机Memory特征、GT Oracle、额外不同k和多seed都可能有价值，但会把本轮从一个有限问题扩展成多机制搜索。先冻结80次观察诊断的预算，若结果不足，明确结束或另起一个最小协议，比在本轮持续追加对照更可靠。

主检验仍存在两个限制：35个非压力病例关联是探索性；后续G3会同时改变锚点与局部配对／空间顺序。因此即使通过，也只能说该整体候选有实证支持，不能写成“已证明模型因离表面远而失效”。

## 六、建议的紧接着一步

确认修订版后，仅开展一次P0有限差量核对：4个D0权重资产、真实观察插入点、拟定40例输入、数值重放合同和资源。然后实施一个观察短入口、完成针对性CPU验证／P3，创建待授权D0 request。此审阅没有创建request或运行内容。
