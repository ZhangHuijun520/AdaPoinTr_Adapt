# FullMamba原计划审阅与关键修订

2026-11-10。结论：**研究方向合理，原稿适合作为起点；但应先消除若干实现与归因歧义，再作为正式执行依据。** 修订版本为同目录v2计划，不覆盖桌面原文件。

## 1. 用户担忧是否成立

担忧有理论和研究设计上的合理性。结构模块的收益可与decoder条件交互发生耦合，换骨干后不能假设增益自动保留。但本项目尚未训练全Mamba decoder，不能声称迁移失败已被观察到，也不能因此否定P1/P2。既然最终架构约束明确，先固定目标主干、再研究创新是减少重复迁移的合理选择。

不需要为了证明这个担忧再额外训练一组“混合创新→全Mamba创新”的迁移矩阵。那将消耗资源却不是当前最短路径。应先建立一个可解释的无注意力参考，并明确是否真的值得继续。

## 2. 原稿值得保留的内容

- 不同时改数据、点数、采样、目标和loss；保持缺失骨块完整边界任务。
- 区分Query自交互和Memory跨集合条件，拒绝仅Mamba(query)冒充Cross-Attention替代。
- 复用历史T0/M0，限制首轮两个新训练，不追求基线阶段堆创新。
- 不以Mamba名称、理论线性复杂度或CPU mock成功代替实际算子、CUDA和科研结果。
- 保留E/J、尾部、风险转移和frontoorbital；不靠GT配准、去离群或筛病例提升Native分数。

## 3. 必须修改的技术问题

### 3.1 真正的attention边界

冻结配置第一层为attn-graph，源码DynamicGraphAttention使用KNN＋MLP＋max而非QK注意力。若按名字全删，会把“替换attention”和“移除局部建模”混在一起。v2保留local graph及对应merge，只替换真正内容注意力；其余实际子类仍须逐语义检查。

### 3.2 公式、顺序与PE

原稿先conditional再self，与母版self→cross→FFN不同，且公式FFN取旧残差、伪代码取新残差不一致。v2统一顺序、FFN读X2，不留训练后更换顺序的自由度。γ不再允许执行者临时挑固定小数或LayerScale；继承原包装。PE只按统一的共享decoder线性投影接入分支，避免query外和层内重复附加而无记录。

### 3.3 条件敏感不等于SSM长程状态有效

原生Mamba既有causal短卷积又有SSM状态；边界前三个Query的变化可能主要由短卷积引起。local cross graph和z也接收输入。v2要求隔离prefix支路、保留短卷积边界token不变并扰动早段Memory，在单层分支出口观察；不能仅查看最终dense并把所有响应归为SSM。

零化特征与零化包含PE的整个token不是一个实验；donor特征/坐标必须成对。donor不能从五个可能同源的病例简单循环后声称跨来源。原稿把整个拼接序列反向扫描说成信息泄漏也需修正：两者来自D，这不是GT泄漏，只是另一种模型语义。

### 3.4 CUDA和计数

原稿“零更新准入”中有最多10个mini-batch optimizer smoke，容易与0-step混报。v2首轮明确全部0 step，分开统计完整模型与decoder-only调用。训练BN状态变化不能要求与eval全状态不变同一判据。数值非确定性先按既有披露处理，不重新开发通用确定性框架。

### 3.5 对照和结论

F0改变decoder算子、位置读出和状态传递，并不严格参数匹配；不能把收益归为SSM单一因素。工程可用不等于非劣、可靠或高精度。原稿2倍警戒线可保留为资源上的科学暂停建议，不能叫工程失败门，也不能作临床门槛。C若暂停D，必须报告两折研究未完成，不报告有选择的跨折成功。

## 4. 文献修正

3DMambaComplete的2026 v2更新标题并明确含Cross-Attention，应与2024 v1去重、区分版本；不能只引用早期摘要支撑纯无注意力结论。BuildingComSSSM出版摘要也明确含self/cross-attention，PPC-MT明确为混合模型。

CompletionMamba、FusionMamba及DAPointMamba提供局部、形状或空间状态建模的先例，不能直接把prefix＋双向scan当成新颖性。MedPCFM/TED提示最终医疗补全论文需要强同任务参照，但当前不强制一并复现所有生成范式。

本次仅重点核验与架构决策直接相关的文献，不声称逐篇精读82项全文；未完整取得的付费页和失败访问均在文献表记录。

## 5. 具体建议

先确认v2设计，再单独进行Stage A有限只读差量核对。不是立即恢复权重或部署服务器；F0从scratch训练，不需要把P1/P2全部历史权重重新上传。Stage A之后再集中实施、针对性CPU/P3及限定CUDA，避免继续逐点滚动准备。

本次没有代码实施、CPU/CUDA测试、新forward、训练、request或服务器操作。H3仍为草案。
