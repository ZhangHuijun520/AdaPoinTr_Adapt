# BCSP-OASG 第二训练种子验证协议 v1

**冻结日期**　2026-11-24（Asia/Shanghai）  
**状态**　协议已冻结，执行待另行授权  
**验证范围**　SkullBreak Fold D，训练 seed `2026112102`，B／A 双臂

## 1. 验证问题与预算

首轮 seed `2026112101` 在 Fold C 和 D 均通过原计划的 6 组门槛。第二种子验证检验的是，在 Fold D 的数据、批序和模型方案固定时，改变共有母版的初始化和训练随机流，A 相对 B 的粗点、密点、接口和严重尾部收益能否按原门槛复现。选择原计划首先开展的 Fold D 作为唯一验证折，限制本轮预算为两次从头训练。Fold C 的第二种子结果不在本协议范围内。

| 环节 | 冻结范围 |
| --- | --- |
| 训练 | `B_D` 后 `A_D`，每臂一次，各 3900 步，合计 7800 步 |
| Native 预测 | 每臂同序 105 例，合计 210 次完整 forward，batch 1、eval、FP32、零更新 |
| 统一 CPU 评分 | 210 行模型评分、105 个病例配对、21 个开发来源、2000 次来源级 bootstrap |
| 裁决 | 先独立判定 Fold D 第二种子，再与首种子的 Fold D 并列报告，并保留首种子的 Fold C 结果 |

## 2. 唯一结构变量

- **B · LQI-Global**。保留原式 $Q^B=\operatorname{reshape}_{256\times3}(g(z))$，其中 $g$ 为原 1024→1024→768 MLP，中间使用 GELU。
- **A · LQI-OASG**。保留 $\Delta_i=h([z,F_i,S_i])$ 与 $Q_i^A=S_i+\Delta_i$，按原生索引使用全部 256 个 Memory 坐标与特征对。$h$ 为共享 1411→1024→384→3 MLP，前两层后使用 GELU，末层线性，各层含 bias。
- 两臂继续共享 Mamba encoder、八层 LQI decoder、FC 密点头和原消费者。每个粗点对应 32 个原生子点。保留原数据表示、8k→8k、D-only 归一化、coarse＋dense Chamfer、原 PyTorch `cdist` 路径、AdamW 参数分组及 LR／BN 调度。训练监督使用固定 GT，预测输入限定为残骨点集与输入侧坐标变换。

## 4. 评分与原门槛

原样使用 Native 世界毫米坐标及 A−B 比较。每例先配对，来源内五类缺损等权，21 个来源等权。按固定来源顺序使用原 PCG64 seed `2026112401` 重采样 2000 次，报告 95% 百分位区间、改善来源数、逐来源留一范围和五类缺损的描述性结果。每项以未舍入数据判定。粗点和密点分层报告，严重状态仍由密点 E P95 >20 mm 或 J Cover@2 = 0 定义。

| 原门槛组 | 保持的通过条件 |
| --- | --- |
| 粗点机制 | E P95 Δ ≤ −0.50 mm。若 B 的粗点 `far20` ≥ 2.00%，Δ`far20` ≤ −1.00 个百分点。否则 A 的粗点 `far20` ≤ 2.00%，且 Δ`far20` ≤ +0.25 个百分点。 |
| 密点收益 | E P95 Δ ≤ −0.50 mm，且至少 14／21 个来源的 E P95 差值严格小于零。 |
| 密点接口 | J P95 Δ ≤ +0.25 mm，J Cover@2 Δ ≥ −0.50 个百分点。 |
| 密点反向风险 | 反向 A2 P95 Δ ≤ +0.50 mm，`far20` Δ ≤ +0.25 个百分点。 |
| 密点严重尾部 | A 的严重病例总数 ≤ B，新增严重病例 ≤ 2／105。报告两臂总数以及新增、挽回、共同严重名单。 |
| 来源级不确定性 | 密点 E P95 差值的 95% 来源级 bootstrap 区间上端严格小于零。 |

第二种子六组均通过，才报告 Fold D 在两个训练种子下均满足原门槛。条件未满足时逐项报告差值和门槛余量，沿用原计划第 8 节的继续／收束规则。若其余门槛通过但区间触零或跨零，则登记为证据不足。病例、执行或配对证据缺失时暂缓裁决。两种子各自报告，来源级区间解释为固定训练权重下的来源差异。当前验证范围为项目内开发数据及两个训练种子，独立来源泛化仍待单独验证。

## 5. 执行顺序与验收

```mermaid
flowchart LR
    accTitle: OASG 第二种子验证顺序
    accDescr: 核验固定资产和随机种子后依次训练基线与候选，完成冻结配对评价后按原门槛裁决。
    prep["资产与新种子准入"] --> b["B_D 训练与冻结"]
    b --> a["A_D 训练与配对冻结"]
    a --> pred["210 次配对预测与冻结"]
    pred --> score["统一 CPU 评分与冻结"]
    score --> gate["原门槛裁决"]
```

1. 先本机复核现有入口中的首种子硬编码、历史初态断言与构造器接口，再做隔离种子适配和针对性 CPU 检查。以实际构造链建立新的共有初态证据，核实两臂起始 RNG 与 A 头冻结字节，随后审查原 CUDA 证据在新入口和实际设备条件下的适用性。数值或接口差异需在训练前查清。
2. 确认设备和容量后，分别冻结版本化请求。B 臂完成正式只读审计后，A 臂绑定 B 的冻结回执。逐批核验完整批序、共有初态、累计曝光和末步 checkpoint SHA256，保留几何、数值和资源日志。
3. 配对 Native 预测保留粗点、密点和原生父子索引，A 额外记录 $S$、$\Delta$ 与 token 索引。核验 $Q=S+\Delta$、归档成员和状态／RNG 证据。统一评分及其冻结审计后，再按第 4 节裁决。
